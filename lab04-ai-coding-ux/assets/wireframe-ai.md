# Text Wireframe (ASCII Layout) จาก AI - ระบบ Inventory Management

เอกสารนี้รวบรวม Prompt และผลลัพธ์ Text Wireframe แบบ ASCII Layout ที่สร้างจาก AI สำหรับ 3 หน้าจอหลัก ได้แก่ หน้าเข้าสู่ระบบ (Login), หน้าแดชบอร์ดสรุปภาพรวม (Dashboard), และหน้าเพิ่มสินค้าใหม่ (Add Product) โดยออกแบบตามหลัก Usability และ Accessibility (WCAG 2.1 AA)

---

## สรุปการใช้ Prompt (ใช้รวม 3 Prompts)
- **Prompt 1:** ออกแบบหน้า Login (เน้นความเรียบง่าย คอนทราสต์ชัดเจน และปุ่มสลับการมองเห็นรหัสผ่าน)
- **Prompt 2:** ออกแบบหน้า Dashboard (เน้นสรุปภาพรวมสต็อก, การแยกสินค้ากายภาพ vs ดิจิทัล, และการ์ดแจ้งเตือนสต็อกต่ำ)
- **Prompt 3:** ออกแบบหน้า Add Product (เน้นป้ายกำกับถาวร, ตัวเลือกประเภทสินค้า, แสดงสถานะ Validation Error และ Success Banner)

---

## 1. หน้าเข้าสู่ระบบ (Login Screen)

### Prompt 1:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Login" ของระบบ inventory
กลุ่มผู้ใช้: พนักงานคลังสินค้า อายุ 34 ปี ทักษะเทคโนโลยีระดับ 2/5 ใช้งานผ่านคอมพิวเตอร์ PC หน้าจอ 1080p

ข้อกำหนด usability:
- ฟิลด์ที่ต้องมี: ชื่อผู้ใช้หรืออีเมล (Username/Email)*, รหัสผ่าน (Password)*
- มีปุ่มสลับการมองเห็นรหัสผ่าน (Show/Hide Password toggle) เพื่อลดการพิมพ์ผิด
- ปุ่มหลัก "เข้าสู่ระบบ" (Primary Action) วางเด่นชัด และมีลิงก์ "ลืมรหัสผ่าน?"
- แสดงสถานะข้อผิดพลาดเมื่อเข้าสู่ระบบไม่สำเร็จ (Invalid credentials error state)

ข้อกำหนด accessibility:
- ทุกฟิลด์ต้องมี Label แสดงถาวรเหนือช่องกรอก (ไม่ใช่ Placeholder อย่างเดียว)
- ช่องบังคับกรอกมีเครื่องหมาย * สีแดงชัดเจน
- ข้อความแจ้งเตือนข้อผิดพลาด (Error Message) ต้องมีไอคอนเตือนร่วมด้วย และบอกแนวทางแก้ไข

ขอผลเป็น ASCII layout พร้อมคำอธิบายว่าแต่ละองค์ประกอบช่วย usability และ accessibility อย่างไร
```

### คำอธิบายด้าน Usability & Accessibility:
- **Visible Labels:** มีป้ายกำกับ "ชื่อผู้ใช้ หรือ อีเมล *" และ "รหัสผ่าน *" ถาวรเหนือช่องกรอก ทำให้ผู้ใช้ไม่ลืมบริบทเมื่อกำลังพิมพ์
- **Show/Hide Password:** ปุ่มรูปดวงตา `[O]` ช่วยให้ผู้ใช้ทักษะระดับ 2 สามารถตรวจสอบตัวอักษรที่พิมพ์ได้ ลดความหงุดหงิดจากการพิมพ์ผิด
- **Accessibility Alert:** กล่องข้อความผิดพลาดมีไอคอน `[!]` ร่วมกับข้อความสีเข้ม ไม่พึ่งพาสีแดงเพียงอย่างเดียว ช่วยให้ผู้มีภาวะตาบอดสีเข้าใจได้ทันที

## 2. หน้าแดชบอร์ดสรุปภาพรวม (Dashboard Screen)

### Prompt 2:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Dashboard" ของระบบ inventory
กลุ่มผู้ใช้: พนักงานคลังสินค้าและผู้จัดการ ทักษะเทคโนโลยี 2/5 ถึง 3/5 ใช้งานผ่านจอ PC 1080p

ข้อกำหนด usability:
- แสดงแถบนำทาง (Navbar) ด้านบน มีชื่อระบบ เมนู "แดชบอร์ด", "รายการสินค้า", "เพิ่มสินค้า", และโปรไฟล์ผู้ใช้
- การ์ดสรุปยอด (Summary Cards): ยอดสินค้าทั้งหมด, ยอดสินค้าที่จับต้องได้ (Physical), ยอดสินค้าดิจิทัล (Digital), และรายการสินค้าใกล้หมด
- ส่วนแจ้งเตือนสต็อกต่ำ (Low Stock Alerts Table): แสดงรายการสินค้าที่เหลือ <= 5 ชิ้น พร้อมปุ่ม "เติมสต็อก (Restock)" รวดเร็ว
- ปุ่มด่วน "เพิ่มสินค้าใหม่ (+ Add Product)" โดดเด่นด้านบนขวา

ข้อกำหนด accessibility:
- ใช้โครงสร้าง Heading ลำดับชัดเจน (H1, H2, H3)
- ตารางมีหัวคอลัมน์ชัดเจน (th) และใช้ Badge แจ้งเตือนที่มีทั้งไอคอน ข้อความ และสีตัดกัน (Contrast >= 4.5:1)
- ลำดับการกด Tab เรียงจากเมนูด้านบน สู่การ์ดสรุป และตารางข้อมูล

ขอผลเป็น ASCII layout พร้อมคำอธิบาย Usability & Accessibility
```

- **Quick Action Buttons:** ปุ่ม `[เติมของ]` วางอยู่ในแต่ละแถวของตาราง ทำให้พนักงานกดเติมสต็อกได้ทันทีโดยไม่ต้องเปิดหลายหน้าต่าง

## 3. หน้าเพิ่มสินค้าใหม่ (Add Product Screen)

### Prompt 3:
```text
ช่วยออกแบบ text wireframe (ASCII layout) สำหรับ "หน้า Add Product" ของระบบ inventory
กลุ่มผู้ใช้: พนักงานคลังสินค้า ทักษะเทคโนโลยี 2/5 ใช้ PC เป็นหลัก ต้องการความถูกต้องในการกรอกสูง

ข้อกำหนด usability:
- ฟอร์มมีฟิลด์:
  * ชื่อสินค้า* (Product Name)
  * รหัสสินค้า* (SKU/Product ID)
  * ชนิดสินค้า* (Radio Button: สินค้าที่จับต้องได้ [Physical] vs สินค้าดิจิทัล [Digital])
  * หมวดหมู่สินค้า (Dropdown)
  * จำนวนสินค้าในคลัง* (Quantity) -> หากเลือกสินค้าดิจิทัล จะปิดใช้งานฟิลด์นี้และแสดงข้อความ "ไม่ต้องระบุจำนวนสต็อก"
  * ราคาต่อหน่วย* (Price in THB)
  * คำอธิบาย/ไฟล์แนบ (Optional)
- ปุ่มการทำงาน: ปุ่มหลัก "บันทึกสินค้า" (Primary Button) สีน้ำเงินเด่นชัด และปุ่มรอง "ยกเลิก" (Secondary Button) วางแยกกัน
- ต้องแสดง State ให้ครบถ้วน:
  1. Success State: แถบข้อความแจ้งเตือนสีเขียว "บันทึกสินค้าสำเร็จเรียบร้อยแล้ว"
  2. Validation Error State: ข้อความเตือนสีแดงพร้อมไอคอนใต้ช่องกรอกที่ผิดพลาด (เช่น "กรุณากรอกราคาเป็นตัวเลขที่มากกว่า 0")

ข้อกำหนด accessibility:
- ทุกฟิลด์มี Label ที่มองเห็นถาวรเหนือช่องกรอก (ไม่ใช่ Placeholder)
- ช่องบังคับมีสัญลักษณ์ดอกจันสีแดง (*) พร้อมข้อความกำกับ
- Error Message อธิบายสาเหตุและวิธีแก้ไขปัญหาชัดเจน
- ลำดับการกด Tab เรียงจากบนลงล่างอย่างเป็นธรรมชาติ

ขอผลเป็น ASCII layout พร้อมคำอธิบาย Usability & Accessibility
```

### คำอธิบายด้าน Usability & Accessibility:
- **Permanent Labels & Required Indicators:** มีป้ายกำกับหมายเลขและชื่อฟิลด์พร้อมดอกจัน `*` ชัดเจน ช่วยให้ผู้ใช้จำได้ตลอดเวลาว่ากำลังกรอกข้อมูลอะไร แม้จะมีการกรอกข้อมูลไปแล้ว
- **Conditional UI for 2 Product Types:** การให้เลือกชนิดสินค้าตั้งแต่ขั้นตอนแรก ช่วยปรับฟอร์มให้เหมาะสม โดยถ้าเลือกสินค้าดิจิทัล ระบบจะ Disable ช่องกรอกจำนวนสต็อกอัตโนมัติ เพื่อป้องกันไม่ให้พนักงานสับสน
- **Clear Action Hierarchy:** ปุ่ม "บันทึกสินค้า" ใช้สี Primary `#1E40AF` ชัดเจน ส่วนปุ่ม "ยกเลิก" เป็น Outline สีเทา และวางห่างกันอย่างเหมาะสม ป้องกันการกดผิดปุ่ม
- **Multi-sensory Error Messages:** ข้อความแจ้งเตือนข้อผิดพลาดใช้ทั้งไอคอนเตือน `[!]` และข้อความอธิบายวิธีแก้ไขที่เข้าใจง่าย เช่น "ราคาต้องมากกว่าศูนย์ (เช่น 150.00)" ไม่ใช้เพียงเส้นขอบสีแดงอย่างเดียว
