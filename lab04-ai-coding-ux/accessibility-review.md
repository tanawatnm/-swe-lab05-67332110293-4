# รายงานการตรวจ Accessibility & Usability (Lab 04)

รายงานนี้บันทึกผลการตรวจสอบ UI Mockup และ Wireframe ตามหลักการออกแบบส่วนต่อประสานที่เข้าถึงได้ (Web Content Accessibility Guidelines - WCAG 2.1 ระดับ AA) พร้อมบันทึกจุดที่ AI ออกแบบผิดพลาดและได้รับการปรับปรุงแก้ไขด้วยตนเอง

---

## 1. ตารางตรวจสอบ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่ปรับปรุงและแก้ไข (Remediation) |
| :--- | :---: | :--- |
| **1. ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | ใช้สีข้อความหลัก `#111827` บนพื้นหลังสีขาว `#FFFFFF` ซึ่งให้ Contrast Ratio สูงถึง **16.1:1** (ผ่านเกณฑ์ WCAG AAA ที่ต้องการ 7:1) ทำให้อ่านง่ายสำหรับผู้ที่มีสายตาเลือนราง |
| **2. ปุ่มหลักมี contrast เพียงพอ** | **ผ่าน** | ปุ่มหลัก (Primary Button) ใช้พื้นหลังสีน้ำเงิน `#1E40AF` ร่วมกับตัวอักษรสีขาว `#FFFFFF` ให้ Contrast Ratio **8.59:1** (ผ่านเกณฑ์ WCAG AAA) มองเห็นเด่นชัด |
| **3. ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | กำหนดให้มีแท็ก `<label>` แสดงชื่อช่องกรอกค้างไว้เหนือช่อง Input ทุกช่องอย่างถาวร ไม่ใช้ Placeholder แทน Label เพื่อไม่ให้ข้อความบอกบริบทหายไปเมื่อเริ่มพิมพ์ |
| **4. ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | กำกับด้วยเครื่องหมายดอกจันสีแดง `*` ติดกับ Label พร้อมระบุคุณลักษณะ `aria-required="true"` และเพิ่มข้อความกำกับสำหรับ Screen Reader |
| **5. error ไม่ได้ใช้สีอย่างเดียว มีไอคอนหรือข้อความด้วย** | **ผ่าน** | ออกแบบกล่อง Error State โดยมีไอคอนเตือน `[ ! ]` ควบคู่กับข้อความสีแดงเข้ม `#DC2626` และบอกสาเหตุพร้อมวิธีแก้ เช่น "ราคาต้องมากกว่าศูนย์ (เช่น 120.00 บาท)" ไม่ใช้เพียงขอบสีแดงอย่างเดียว |
| **6. ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | จัดลำดับ Focus Order (TabIndex) ตามธรรมชาติของการอ่าน (Top-to-Bottom, Left-to-Right) โดยไล่จากประเภทสินค้า > SKU > ชื่อ > หมวดหมู่ > จำนวน > ราคา > ปุ่มยกเลิก > ปุ่มบันทึก |
| **7. ปุ่มมีชื่อบอกหน้าที่ ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | เปลี่ยนชื่อปุ่มทั้งหมดให้สื่อความหมายของการกระทำโดยตรง เช่น "บันทึกสินค้า (Save)", "ยกเลิก (Cancel)", "เข้าสู่ระบบ (Sign In)", "เติมสต็อก (Restock)" หลีกเลี่ยงคำคลุมเครือ เช่น "OK", "Submit", หรือ "X" |

## 2. จุดที่ AI ออกแบบผิดพลาด และการแก้ไขด้วยตนเอง (อย่างน้อย 2 จุด)

จากการสังเกตและวิเคราะห์ผลลัพธ์แรกที่ AI coding/design assistant สร้างขึ้น พบข้อผิดพลาดด้าน Accessibility และ Usability ที่แฝงอยู่ 3 จุดสำคัญ ซึ่งผู้จัดทำได้แก้ไขด้วยตนเอง ดังนี้:

### จุดที่ 1: AI ใช้ Placeholder แทน Label ถาวร (Cognitive & Visual Context Loss)
- **สิ่งที่ AI ทำพลาด:** ในแบบฟอร์มหน้า Add Product ครั้งแรก AI ออกแบบโดยตัดป้ายกำกับด้านบนออก แล้วใส่ข้อความจาง ๆ ลงในช่อง Input แทน (เช่น `<input placeholder="กรอกชื่อสินค้าที่นี่...">`) เพื่อให้หน้าตาดูเรียบง่ายทันสมัย
- **ผลกระทบ:** เมื่อผู้ใช้ (เช่น พนักงานคลังทักษะระดับ 2) คลิกเริ่มพิมพ์ ตัวอักษร Placeholder จะเลือนหายไปทันที หากพนักงานละสายตาไปนับของในโกดังแล้วหันกลับมา จะลืมว่าช่องนี้คือช่องจำนวนสินค้าหรือราคาสินค้า ทำให้กรอกข้อมูลสลับกัน
- **การแก้ไขด้วยตนเอง:** เพิ่มข้อความ `<label>` ขนาด 13px สี `#111827` หนาปานกลาง วางค้างไว้เหนือช่องกรอกทุกช่องอย่างถาวร พร้อมผูก `for="input_id"` และเพิ่มคำแนะนำ (Helper text) ไว้ใต้ช่องแยกต่างหาก

### จุดที่ 2: AI ใช้สีเทาอ่อนที่มี Contrast Ratio ต่ำกว่าเกณฑ์มาตรฐาน (Failing WCAG AA)
- **สิ่งที่ AI ทำพลาด:** AI เลือกใช้สีเทาอ่อน `#9CA3AF` บนพื้นหลังสีขาว `#FFFFFF` สำหรับข้อความช่วยเหลือ (Helper Text) และป้ายบอกชนิดสินค้า ซึ่งเมื่อคำนวณอัตราส่วน Contrast Ratio จะได้เพียง **2.54:1** (ไม่ผ่านเกณฑ์ WCAG AA ที่กำหนดขั้นต่ำ 4.5:1 สำหรับข้อความขนาดปกติ)
- **ผลกระทบ:** ผู้ใช้ที่มีสายตาเลือนราง หรือพนักงานที่ทำงานในโกดังที่มีแสงสะท้อนบนหน้าจอคอมพิวเตอร์ จะมองไม่เห็นข้อความช่วยเหลือและอ่านข้อกำหนดไม่ชัดเจน
- **การแก้ไขด้วยตนเอง:** ปรับเปลี่ยนชุดสีของข้อความช่วยเหลือและป้ายกำกับรองมาใช้สีเทาเข้ม `#4B5563` ซึ่งให้ Contrast Ratio สูงถึง **7.46:1** และข้อความสำคัญใช้สี `#111827` (16.1:1) ผ่านเกณฑ์ทั้ง WCAG AA และ WCAG AAA

### จุดที่ 3: Error State พึ่งพาสีแดงเพียงอย่างเดียว และข้อความไม่บอกวิธีแก้ไข
- **สิ่งที่ AI ทำพลาด:** เมื่อกรอกข้อมูลผิดพลาด เช่น ใส่ราคา 0 บาท AI แสดงผลเพียงเปลี่ยนเส้นขอบช่อง Input เป็นสีแดง `#EF4444` และแสดงข้อความสั้น ๆ ว่า "ข้อมูลไม่ถูกต้อง (Invalid Input)"
- **ผลกระทบ:** ละเมิดหลักการ WCAG ข้อ 1.4.1 Use of Color (ห้ามใช้สีเป็นตัวบ่งชี้สถานะเพียงอย่างเดียว) ทำให้ผู้ใช้ที่มีภาวะตาบอดสีแดง-เขียว (Protanopia / Deuteranopia) แยกไม่ออกว่าช่องใดเกิดข้อผิดพลาด นอกจากนี้ข้อความไม่บอกว่าผิดเพราะอะไร ทำให้ผู้ใช้ไม่รู้วิธีแก้ไข
- **การแก้ไขด้วยตนเอง:** ปรับปรุง Error State ให้สมบูรณ์แบบ:
  1. เพิ่มไอคอนเครื่องหมายตกใจสีแดง `[ ! ]` นำหน้าข้อความ
  2. เปลี่ยนสีพื้นหลังช่อง Input เป็นสีแดงอ่อน `#FEF2F2` ร่วมกับเส้นขอบหนา 2px สี `#DC2626`
  3. เขียนข้อความอธิบายสาเหตุและวิธีแก้ไขอย่างชัดเจน เช่น `[ ! ] ข้อผิดพลาด: ราคาต้องมากกว่าศูนย์ (เช่น 120.00 บาท)`
